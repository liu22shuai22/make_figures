# 语义沙执行面规划与验收

欢迎页和工作台共用 `POST /api/assistant/turn`。前端提交当前页面、图种、最近八条消息和可供编辑的 E-R 草稿。服务端从会话令牌解析登录身份。客户端指定的页面和图种用于选择适用工具，账号权限由服务端决定。

## 已落地

1. **执行入口和路由。** 整条消息先经过策略检查。明确的产品操作走规则；其他请求在账号有可用渠道时尝试模型路由。模型输出只接受登记过的通道和工具组合，模型失效时使用规则。草稿中存在联系不会自动触发基数修改。
2. **工具访问控制。** 注册表在执行每个工具前检查策略。FAQ、用量说明、渠道说明、受控百科可在欢迎页和工作台使用。百科检索失败后，已登录用户可使用模型简答。结构检查在工作台使用，基数建议还要求登录、E-R 图和有效二元联系。当前端点数组和旧式 a/b 端点都能识别。
3. **组合指令（轻量多工具）。** 输入明确的连接词或分句标点时，可在一轮内顺序执行 2–3 个**不同**的产品工具（FAQ / 用量 / 渠道 / 打开检查 / 基数建议）。各分句只用规则路由（不拆百科外联、不叠多次付费模型）。`trace.combined` / `trace.tools` 标出是否组合。基数修改仍须用户选择并确认；结构检查在前端检查视图执行。
4. **统一权限表。** `policy.check_access` 在注册表执行前统一校验 surface / 登录 / 图种；组合请求中每一步单独拦。
5. **百科与追问。** 使用受控 Wikipedia 检索、标题消歧和短历史承接主题。回复显示来源，模型回退单独标注。
6. **观测和回看。** 「执行记录」可展开策略 / 路由 / 工具状态与耗时。游客仅本页内存；登录账号经 `GET /api/assistant/traces` 回看最近 30 轮（只存步骤元数据，打开历史不重放）。

## 实施取舍

组合请求采用有上限的串行编排，保留结果顺序。百科追问和含糊请求仍按整句路由。任意网址抓取和自主 ReAct 循环继续在范围之外。Token 用量入口打开现有的本机渠道统计页，其统计口径是整个实例。

## 验收路径

- 在欢迎页输入「怎么开始？顺便查看Token用量」，应依次得到入门说明和用量入口。
- 在工作台载入选课样例，登录后输入「检查模型，然后限制每个学生最多选一门课程」。应收到检查入口和课程端改为 1 的建议，点确认才应用。
- 用游客身份发送相同请求，检查入口可用，基数步骤提示登录。切换到用例图时，检查视图使用用例草稿的结构问题。
- 打开「执行记录」查看各步状态。刷新后登录账号可回看，切换账号只显示该账号记录。
- 后端回归运行 `python -m unittest tests.test_assistant_plane`；前端构建运行 `npm.cmd --prefix frontend run build`。

## 代码入口

执行面位于 `assistant/plane.py`、`harness.py`、`policy.py`、`router.py`、`registry.py`、`tools/`、`memory.py` 和 `trace_store.py`。HTTP 接口位于 `api.py`，界面位于 `frontend/src/components/AiAssistant.tsx`。最初四阶段的历史提交为 `5c3920a`。
